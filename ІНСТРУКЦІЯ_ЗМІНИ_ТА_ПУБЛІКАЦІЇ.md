# DJ_SKY_STYLE RADIO — інструкція зі зміни та публікації

Цей документ пояснює, де редагувати сайт, як запустити його на комп’ютері та як опублікувати через **GitHub → Vercel**. Усі команди нижче призначені для Windows PowerShell у папці `D:\RADIO`.

> Важливо: не додавайте у GitHub пароль трансляції Caster.fm, API-ключі чи файл `.env.local`. Вони вже виключені через `.gitignore`.

## 1. Швидка карта файлів

| Що потрібно змінити | Файл | Що саме редагувати |
| --- | --- | --- |
| Плеєр Caster.fm Free | `.env.local` | `NEXT_PUBLIC_CASTER_PUBLIC_TOKEN`, за потреби `NEXT_PUBLIC_CASTER_CHANNEL_ID` |
| URL публічної сторінки Caster.fm | `.env.local` | `NEXT_PUBLIC_STATION_URL` |
| Справжній direct stream (якщо з’явиться платний тариф) | `.env.local` | `NEXT_PUBLIC_RADIO_STREAM_URL` |
| Посилання на соцмережі, Telegram, контакти | `config/socials.ts` | поля `href`, `telegramUrl`, `contactDetails` |
| Розклад передач | `data/schedule.ts` | дні, час та назви ефірів |
| Текст «Про станцію» | `config/content.ts` | поле `about` |
| Назва станції та технічні налаштування | `config/radio.ts` | `stationName`, параметри Caster.fm |
| Вигляд, кольори, адаптивність | `app/globals.css` | CSS-змінні на початку та стилі компонентів |
| Маршрути та склад сторінок | `app/` | `page.tsx` у кожній папці |

## 2. Налаштування безкоштовного плеєра Caster.fm

Безкоштовний план Caster.fm не дає загальнодоступний Direct Stream Link для власного HTML5-плеєра. У цьому сайті використано офіційний віджет Caster.fm.

1. У Caster.fm відкрийте **Widgets / Players**.
2. Виберіть **Live Stream Player**, темну тему та канал `DJ_SKY_STYLE РАДІО`.
3. У коді віджета знайдіть значення після `data-publicToken="..."`.
4. Відкрийте файл `D:\RADIO\.env.local` у Блокноті:

   ```powershell
   Set-Location D:\RADIO
   notepad .env.local
   ```

5. Заповніть або перевірте ці рядки:

   ```env
   NEXT_PUBLIC_CASTER_PUBLIC_TOKEN=ваш_public_token_з_Caster.fm
   NEXT_PUBLIC_CASTER_CHANNEL_ID=
   NEXT_PUBLIC_STATION_URL=https://djskystyle.ismyradio.com
   ```

6. Якщо в Caster.fm у коді віджета є `data-channelId="..."`, скопіюйте його після знака `=` у `NEXT_PUBLIC_CASTER_CHANNEL_ID`. Якщо поле порожнє, залиште порожнім і тут.
7. Збережіть файл. Перезапустіть локальний сервер, якщо він був запущений: у PowerShell натисніть `Ctrl+C`, після чого знову виконайте команду запуску з наступного розділу.

`public token` можна розміщувати в сайті: Caster.fm спеціально створює його для вбудованого віджета. **Пароль трансляції (source password) не можна нікому надсилати й не можна вставляти в цей проєкт.**

## 3. Локальний запуск і перевірка

1. Відкрийте PowerShell.
2. Виконайте:

   ```powershell
   Set-Location D:\RADIO
   & "C:\Program Files\nodejs\npm.cmd" install
   & "C:\Program Files\nodejs\npm.cmd" run dev
   ```

   Саме `npm.cmd` потрібен, якщо PowerShell показує помилку про заборону запуску `npm.ps1`.

3. Відкрийте у браузері [http://localhost:3000](http://localhost:3000).
4. Перевірте кожну сторінку:

   - `http://localhost:3000/`
   - `http://localhost:3000/radio`
   - `http://localhost:3000/schedule`
   - `http://localhost:3000/history`
   - `http://localhost:3000/about`
   - `http://localhost:3000/contact`

5. На `/radio` натисніть кнопку відтворення у **вбудованому віджеті Caster.fm**. Браузер не має запускати звук автоматично — це нормальна вимога браузерів.

Щоб перевірити production-версію перед відправленням онлайн:

```powershell
& "C:\Program Files\nodejs\npm.cmd" run build
& "C:\Program Files\nodejs\npm.cmd" run start
```

Зупинити сервер можна натисканням `Ctrl+C` у тому ж вікні PowerShell.

## 4. Зміна контенту сайту

### Соцмережі й контакти

Відкрийте `D:\RADIO\config\socials.ts`:

```powershell
notepad .\config\socials.ts
```

Приклад заповнення:

```ts
{ label: "Instagram", href: "https://instagram.com/your_account", icon: Instagram },
...
export const telegramUrl = "https://t.me/your_channel";

export const contactDetails = {
  email: "hello@example.com",
  telegram: "https://t.me/your_channel",
  instagram: "https://instagram.com/your_account",
} as const;
```

Якщо `href` порожній (`""`), кнопка не показується. Це захищає сайт від порожніх або вигаданих посилань.

### Розклад

Відкрийте `D:\RADIO\data\schedule.ts`:

```powershell
notepad .\data\schedule.ts
```

Приклад одного дня:

```ts
{
  day: "П’ятниця",
  shows: [
    { time: "20:00", title: "DJ_SKY_STYLE" },
    { time: "23:00", title: "Нічний сет" },
  ],
},
```

### Текст про радіо

Відкрийте `D:\RADIO\config\content.ts` і змініть текст у `about`.

### Форма «Замовити трек»

Форма на `/contact` не надсилає дані «в нікуди». Щоб вона справді працювала, створіть власний захищений endpoint (наприклад, серверless function або Telegram Bot relay) і додайте в `.env.local`:

```env
NEXT_PUBLIC_REQUEST_TRACK_ENDPOINT=https://ваш-домен/api/request-track
```

Endpoint має приймати `POST` JSON такого вигляду:

```json
{
  "name": "Ім’я слухача",
  "artist": "Виконавець",
  "track": "Назва треку",
  "message": "Коментар"
}
```

## 5. Підготовка Git на комп’ютері

Спершу перевірте, чи встановлений Git:

```powershell
git --version
```

Якщо PowerShell не знаходить команду `git`, встановіть **Git for Windows** з [git-scm.com](https://git-scm.com/download/win), залиште стандартні налаштування інсталятора, закрийте PowerShell і відкрийте його знову.

Якщо це перший Git-проєкт на вашому комп’ютері, один раз налаштуйте підпис комітів. Вкажіть своє ім’я та email, прив’язаний до GitHub:

```powershell
git config --global user.name "Ваше ім’я або DJ_SKY_STYLE"
git config --global user.email "ваш-email@example.com"
```

Перевірка:

```powershell
git config --global user.name
git config --global user.email
```

## 6. Створення репозиторію на GitHub

1. Увійдіть або зареєструйтеся на [GitHub](https://github.com/).
2. Натисніть `+` у верхньому правому куті → **New repository**.
3. Заповніть:
   - **Repository name:** `dj-sky-style-radio`
   - **Description:** `Website for DJ_SKY_STYLE RADIO`
   - **Visibility:** `Public` або `Private`.
4. Дуже важливо: **не ставте** галочки `Add a README file`, `.gitignore` або `Choose a license`. У папці сайту ці файли вже є; порожній репозиторій убереже від конфлікту.
5. Натисніть **Create repository**.
6. На сторінці **Quick setup** скопіюйте HTTPS-адресу репозиторію. Вона виглядає так:

   ```text
   https://github.com/ВАШ-ЛОГІН/dj-sky-style-radio.git
   ```

GitHub офіційно радить створювати порожній репозиторій без README, license і gitignore, коли ви надсилаєте вже готовий локальний проєкт. [Інструкція GitHub](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github)

## 7. Завантаження коду на GitHub — точні команди

1. У PowerShell виконайте:

   ```powershell
   Set-Location D:\RADIO
   git init
   git add .
   git status
   ```

2. Переконайтеся, що в переліку **немає** `.env.local`. Якщо його немає — все правильно.
3. Збережіть першу версію сайту:

   ```powershell
   git commit -m "Створено сайт DJ_SKY_STYLE RADIO"
   git branch -M main
   ```

4. Підключіть GitHub-репозиторій. Вставте **ваш скопійований URL** замість прикладу:

   ```powershell
   git remote add origin https://github.com/ВАШ-ЛОГІН/dj-sky-style-radio.git
   git remote -v
   ```

5. Якщо `git remote -v` показує ваш URL двічі (`fetch` і `push`), завантажте код:

   ```powershell
   git push -u origin main
   ```

6. Під час першої відправки GitHub відкриє браузер для авторизації або попросить увійти. Підтвердіть авторизацію тим акаунтом, на якому створили репозиторій.
7. Поверніться на сторінку репозиторію GitHub і оновіть її: мають з’явитися папки `app`, `components`, `config`, `data`, `lib`.

### Якщо щось пішло не так

| Помилка | Дія |
| --- | --- |
| `Author identity unknown` | Виконайте дві команди `git config --global user.name` та `git config --global user.email` з розділу 5, потім повторіть `git commit`. |
| `remote origin already exists` | Перевірте `git remote -v`. Для заміни адреси: `git remote set-url origin https://github.com/ВАШ-ЛОГІН/dj-sky-style-radio.git` |
| `repository not found` | Перевірте GitHub URL, логін і те, що ви авторизовані в правильному акаунті. |
| GitHub просить пароль | Звичайний пароль GitHub для Git через HTTPS не використовується. Завершіть авторизацію у браузері або скористайтеся personal access token за інструкцією GitHub. |
| У GitHub потрапив `.env.local` | Негайно змініть усі дані з файлу в сервісах, видаліть файл з історії Git і зверніться за допомогою до розробника. Не достатньо просто видалити його новим комітом. |

## 8. Публікація сайту у Vercel

GitHub зберігає код. Щоб сайт працював для слухачів, розгорніть його у Vercel.

1. Відкрийте [Vercel](https://vercel.com/) і увійдіть через той самий GitHub-акаунт.
2. Натисніть **Add New → Project**.
3. Знайдіть `dj-sky-style-radio` і натисніть **Import**.
4. На екрані налаштувань:
   - **Framework Preset:** Next.js (Vercel має визначити його автоматично).
   - **Root Directory:** `./`.
   - **Build Command:** залиште стандартний.
5. Перед першим Deploy відкрийте блок **Environment Variables** та додайте:

   | Name | Value | Environment |
   | --- | --- | --- |
   | `NEXT_PUBLIC_CASTER_PUBLIC_TOKEN` | ваш token з Caster.fm Widgets / Players | Production, Preview, Development |
   | `NEXT_PUBLIC_CASTER_CHANNEL_ID` | channel ID або порожнє значення | Production, Preview, Development |
   | `NEXT_PUBLIC_STATION_URL` | `https://djskystyle.ismyradio.com` | Production, Preview, Development |

   Якщо згодом з’явиться документований Caster.fm API, додайте `CASTER_API_URL`, `CASTER_API_TOKEN`, `CASTER_STATION_ID`. Ці три значення не повинні починатися з `NEXT_PUBLIC_`, якщо містять секретні дані.

6. Натисніть **Deploy** і зачекайте завершення збірки.
7. Натисніть **Visit**. Ви отримаєте безкоштовну адресу приблизно такого формату:

   ```text
   https://dj-sky-style-radio.vercel.app
   ```

8. Відкрийте `/radio` на телефоні та натисніть Play у Caster.fm player. Перевірте також усі інші сторінки.

Змінні середовища застосовуються до наступного deployment, тому після зміни будь-якої змінної у Vercel відкрийте **Deployments** і натисніть **Redeploy** для production deployment. [Vercel: Environment Variables](https://vercel.com/docs/environment-variables)

## 9. Як оновлювати сайт після публікації

Після зміни файлів виконайте:

```powershell
Set-Location D:\RADIO
git status
git add .
git commit -m "Оновлено розклад та контент"
git push
```

Кожен `git push` у гілку `main` автоматично запускає новий production deployment у Vercel. Перед цим можна створити окрему гілку для тесту — Vercel дасть їй окрему Preview-адресу. [Vercel: Git Deployments](https://vercel.com/docs/git)

## 10. Власний домен

Після робочого деплою у Vercel відкрийте **Project → Settings → Domains → Add Domain**, введіть куплений домен і додайте DNS-записи, які покаже Vercel, у панелі вашого реєстратора домену. HTTPS-сертифікат Vercel оформить автоматично після правильного DNS-підключення. [Vercel: Custom Domains](https://vercel.com/docs/domains/working-with-domains/add-a-domain)
